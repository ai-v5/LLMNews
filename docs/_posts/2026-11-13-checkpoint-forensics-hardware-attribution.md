## 先给判断：方法有价值，结论必须分层

这不是靠模型回答风格猜硬件，也不是从 `import torch_npu` 反推训练平台，而是尝试从公开权重中恢复**初始化随机数及其排列方式**。

最值得肯定的地方是：作者把猜测推进到了可检验的数值预测，并报告了实机重建、保留样本验证与供应商数值差异测试。最需要警惕的是：**同一初始化能在不同平台上继续训练，软件也能模拟另一种排列；因此初始化的证据强度，不能直接转移给“全程训练”“芯片所在地”“采购途径”等不同命题。**

以下区分三层：作者报告了什么、公开实现能解释什么、本文的独立分析是什么。本文没有取得这些模型完整训练日志，也没有独立重跑作者的全量搜索。

## 三、调查方法：硬件为何会影响随机数排列

对照原文：[调查方法](https://unemploymentlabs.com/checkpoint-forensics#investigation)。

方法的端到端流程可以概括为：寻找保留行并对齐张量 → 搜索 seed、offset 与布局候选 → 冻结候选，在未参与选择的张量上预测 → 实机重建并测试替代后端 → 最后才解释可能的硬件来源。完整搜索脚本尚未公开可直接取得，不能把这一流程摘要当成已独立复现。

报告的型号对应关系是：148 布局对应其测试的 B200/B300，152 对应 GB200/GB300，132 对应 H100 SXM/H800/H200。这些是特定设备配置类别，不等于 NVIDIA 整个架构代际都只有这一种指纹。

### 1. PRNG 不是不可预测噪声

给定 seed、counter 和映射规则，伪随机数生成是确定性计算。Philox 并非 NVIDIA 专属算法；真正可见的特征，是随机流如何分给线程、线程把值写到哪些位置，以及数值变换与舍入方式。

[PyTorch 的 CUDA 实现](https://github.com/pytorch/pytorch/blob/main/aten/src/ATen/native/cuda/DistributionTemplates.h)中，相关执行路径先按元素数计算 grid，再按设备属性限制 grid。把源码关系简化为：

```text
grid = min(ceil(numel / block_size), SM_count × blocks_per_SM)
blocks_per_SM = floor(maxThreadsPerMultiProcessor / block_size)
```

若以 `maxThreadsPerMultiProcessor=2048` 作条件示例，132/148/152 SM 对应封顶后的 270,336/303,104/311,296 个逻辑线程；这不是实际同时驻留的线程数，也不是设备序列号。小张量未触及上限时，布局可能无法区分这些设备。

这是一个**软件选择的启动配置**，不是硅片主动写入权重的不可伪造序列号。还要确定该模型使用了哪个版本、哪个分布与哪个初始化入口，不能把当前 main 的代码无条件套到历史训练。

### 2. 为什么只看 SM 数不够

同一个总线程布局可能来自不同的 SM 数和每 SM 线程上限；小张量甚至没有碰到设备上限。进一步还要核对 dtype、正态变换、Philox offset、调用顺序、分片大小、展平次序、转置和 checkpoint 保存排列。

因此更合适的待识别对象是：

> 初始化算法 × 软件版本 × 数值路径 × 启动布局 × 参数排列

设备型号是对这组配置的解释之一，而不是直接观测量。

### 3. 为什么训练后还能留下痕迹

令最终参数为 `W = W₀ + ΔW`。如果某些位置没被更新，或者更新没有完全覆盖初始化的差异，就可能测到 `W` 与候选 `W₀` 的相关。未使用的 embedding 行、保留 token 等位置可能提供更强线索，但必须检查它们确实属于训练 checkpoint，而非导出时追加或重建的权重。

一个替代解释很具体：转换脚本为新词表扩展行做初始化，可能暴露的是**转换机器**，不是训练机器。识别工作应优先比较多个层、多个张量和不同训练阶段，而非只挑出最好匹配的一组行。

## 四、限制：把硬件归因拆成六个问题

对照原文：[限制](https://unemploymentlabs.com/checkpoint-forensics#limitations)。

| 待判断的问题 | 初始化指纹单独能否回答？ |
|---|---|
| 是否存在同源初始化模式？ | 在充分复现与对照下，可以有很强证据。 |
| 哪种常见软件/硬件配置能生成它？ | 可以提出并验证候选，但需排除配置等价。 |
| 哪个物理设备实际执行了初始化？ | 需要考虑软件模拟、移植、继承和导出过程。 |
| 哪些设备执行了预训练和后训练？ | 不能只靠初始化判断。 |
| 集群卡数、训练时间、成本是多少？ | 不能。 |
| 芯片位于何处、是否违反法律？ | 不能。 |

作者讨论了受限制配置的 AMD 设备能重现相同布局。这一点非常重要：它说明“布局匹配”是硬件归因的中间环节，而非终点。

即使标准 PyTorch 不能让某款较小 GPU 自然生成较大设备的默认布局，也不能据此证明它在计算上无法生成相同数组。CPU、GPU 上的自定义 kernel 或离线模拟都能按指定 counter 和索引映射计算。这里不是说某家公司这样做过，而是说明**技术唯一性需要针对生成机制证明，不能只针对默认设备列表证明**。

同样，未检出 NVIDIA 指纹，既不证明使用昇腾，也不证明没有使用 NVIDIA。[LongCat 官方模型卡](https://huggingface.co/meituan-longcat/LongCat-2.0/blob/main/README.md)的 ASIC 训练声明应作为独立证据看待；[V4.1-Flash](https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash)的阴性搜索结果不能自动成为另一种芯片的阳性证据。初始化在 A 平台、预训练在 B 平台、后训练在 C 平台的过程，也完全可能保留 A 的痕迹。

## 五、验证部分：极高 sigma 不等于极高硬件后验概率

对照原文：[验证](https://unemploymentlabs.com/checkpoint-forensics#verification)。

报告包含保留数据测试、实机复现、seed 相邻值对照，以及与公开硬件声明的一致性检查。这些都比仅展示一张相关性图更扎实。

但检验有两层，不能混淆：

1. **偶然匹配问题：**随机无关权重碰巧得到这个分数的概率有多大？
2. **归因问题：**能产生这个模式的不同机制中，哪个实际发生了？

即使第一层的偶然概率极低，第二层仍可能存在多个解释。`sigma` 不是“Blackwell 训练概率”，也不是对集群规模的置信度。

对约 `6×10¹²` 次独立标准高斯单侧比较，令 `N·P(Z>z)≈1`，得到约 `7.3σ`；`8σ` 是更保守的量级。但实际候选共享数据、不同层和行可能相关，筛选过程还可能引入选择偏差，不能只把元素数当独立样本数。需要公开统计量定义、有效样本量、扫描范围、完整负对照分布，以及事先固定的验证集。

“24 个已知模型都一致”也不是已经证明 100% 准确率：其中 11 个是 step-zero checkpoint，且包含共享初始化的模型和披露范围较宽的训练说明。应报告按独立训练谱系划分的混淆矩阵，而不只是模型名称数。

## 七、最有价值的启示：从指纹宣传走向训练来源审计

### 对模型开发者

保留 step-zero checkpoint、训练阶段之间的迁移记录、随机状态和签名日志，比靠最终权重反推历史更可靠。公开披露可分别列出初始化、预训练、继续训练、后训练、量化和导出平台，避免“使用某硬件”一句话承载六种含义。

### 对昇腾等跨平台训练系统

最关键的实验不是“能否检出某个阴性模型”，而是受控的跨平台盲测：

| 实验 | 要回答的问题 |
|---|---|
| A 初始化，A 训练 | 建立平台内基线。 |
| A 初始化，B 训练 | 测量旧平台指纹保留多久。 |
| B 初始化，A 训练 | 排除把训练平台误判为初始化平台。 |
| CPU 初始化，A/B 训练 | 测量方法漏检和不可识别范围。 |
| 相同初值，改变软件版本、精度或启动布局 | 测量对软件而非硬件变化的敏感度。 |
| 合并、量化、词表扩展和转换后再测 | 区分继承、破坏与新增模式。 |

另外，跨平台性能或精度对照应固定同一份 step-zero checkpoint，再比较训练收敛和数值漂移；否则初始化差异会混入平台差异。

把模型规模、优化器、权重衰减、token 数、冻结策略和随机状态固定，分阶段采样，再让不知道实验分组的人盲判。这样的评估才能估计误报率、漏报率，以及“识别初始化”与“识别训练平台”的差距。

### 对性能与成本推断

原帖估计最大的 Kimi K3 和 DeepSeek-V4-Pro 各约 2–3 千张卡、每个集群约 1.5–2 亿美元、合计超过 5 亿美元等估计，不是指纹测量。完整报告的[表 2](https://unemploymentlabs.com/checkpoint-forensics#table-2)进一步列出五次 run 约 1,700/2,700/3,400/1,400/1,400 张、合计约 12,000（7,000–20,000）的估计；其中 K3 的 3,400（1,000–9,500）与原帖约 2–3 千是不同表述。作者明确不自信，部分 token 量为估计，采用不同训练天数、利用率和初始化平台等于训练平台的假设。各 run 的估计求和不等于独立实物数量或同时占用量；约 7 万美元/卡也是借助另一报道推算的价格。

卡数需要额外变量。粗略关系为 `N ≈ F / (P_peak × MFU × t)`，其中 `F` 是实际训练计算量，`t` 是训练时长。指纹没有给出这些量，也无法判断机器是购买、租用、跨项目复用还是跨阶段变更。不能从 148/152 的布局标签直接跳到数千张卡和数亿美元采购额。

**最终判断：这是值得复现的初始化取证技术，不是完整训练履历的替代品。**认可其数值证据，同时拒绝把初始化、训练、地理位置与合规状态连成一条未经验证的等号，才是这项工作最有价值的读法。
