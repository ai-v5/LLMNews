**共享权重只计一遍，执行共享层要按实际遍数计费。** U-MoLT 的 700M 对照把这件事量化了：参数只多 1.5%，达到基线最终验证损失少读 41.8% 的 token，但沿论文已经跑出的学习率轨迹，仍比基线多花约 17% 的理论训练 FLOPs。它证明了在这一实验中模型更省数据，没有证明更省训练算力。

选题材料复核截至北京时间 **11 月 27 日 05:30**。论文 v1 提交于 11 月 25 日 18:58 UTC，列入 [arXiv 11 月 26 日 cs.LG 公告](https://arxiv.org/list/cs.LG/recent)。以下区分作者报告的实测、根据论文数字做的换算和未验证的外推。

## 一、模型到底循环了什么？

普通的深层 Transformer 每个 block 顺序跑一次。直接加循环，可以再跑一遍同样的 block，把首轮隐状态喂回去。MoLT 系列探索的区别，是把部分跨轮信息放到 **KV 记忆**：后续位置在处理自己时，可以读取此前位置形成的记忆，而不必让当前 token 在推理阶段把整个栈原样重跑。

U-MoLT 把栈分成两段。编码器构建记忆，结合本轮的局部 KV 与严格前缀的记忆 KV；解码器通过因果交叉注意力读取编码器输出，生成用于预测的表示。严格前缀只包含当前位置之前的 token，因此不能借跨轮记忆读取未来答案。推理走 Hybrid-2 时，prompt 做两轮并行 prefill，第一枚续写 token 的分布来自最后一个 prefill 位置；之后每一步只跑一次编码器和解码器并扩展保留的缓存。这个逐位置递推与训练时同一批 token 全部走两轮不是同一执行图。

对性能建模，至少分开三件事：

- **容量**：按唯一张量和分片算权重、梯度与优化器状态。KV、激活和临时缓冲要按实现另外算，不随共享权重同比缩减。
- **每 token 算力**：按阶段统计真正执行的 block、attention、投影和预测头；训练还要计反向、重算等开销。不能拿唯一参数直接套一个统一的 6N。
- **实际时间**：在 FLOPs 之外，测计算吞吐、通信、内存流量和关键路径。循环权重怎么放到 PP stage，可参看站内 [Loop-PP]({{ '/2026/11/25/loop-pp-recurrent-training/' | relative_url }})；那是另一种架构下的调度问题。

## 二、同样的 token、同样的损失、同样的预算，答案各是什么？

论文附录 A 的两组从零训练均使用 64 张 H20、4,096 token 上下文和同一份 400B-token 数据。基线是 38 层 OLMo3；U-MoLT 把 38 个 block 分成 19 层编码器和 19 层解码器，共享参数执行两轮。作者只用最终一轮的输出做验证，省掉首轮解码器，验证执行为 57 次。

| 400B token 完整训练 | OLMo3 | U-MoLT | 变化 |
| --- | ---: | ---: | ---: |
| 唯一可训练参数 | 700.53M | 711.02M | +1.50% |
| block 执行数，训练 / 论文验证 | 38 / 38 | 76 / 57 | 2.00× / 1.50× |
| 理论训练 FLOPs | 1.00× | 2.01× | 约翻倍 |
| 墙钟时间 | 110.1 h | 219.2 h | 1.99× |
| 峰值活跃 GPU 显存 | 43.6 GiB | 58.4 GiB | 1.34× |
| 11 个领域等权验证交叉熵 | 2.598 | 2.553 | −0.045 |

**同 token：** 验证损失较低，但算力与时间接近翻倍。损失差折算成跨领域困惑度几何均值约下降 4.4%，不等于任务准确率统一增加 4.4 个点。

**同损失：** 论文在已运行的验证曲线上插值，U-MoLT 在 232.8B token 达到基线读完 400B token 的损失。它省下 167.2B 个数据 token；但论文的理论 FLOP 账，早到 198.9B 就耗完这份基线预算。按固定运行配置换算，`232.8 / 198.9 ≈ 1.17`。对这个配方，每 token 成本约两倍，要打平算力，数据用量须降到基线约一半，41.8% 的节省尚未跨过这条线。

**同预算：** 198.9B 是完整 400B 余弦调度中途的预算刻度，不是用同等总 FLOPs 重新选定结束点并完成退火的一次训练。要决定是不是值得训练下一代模型，应重新跑等 FLOP、等墙钟或等 GPU 小时的完整配方，报告损失及下游指标，并在多个规模上确认交叉点是否移动。这个结果也不能当作 [GLM-5.4]({{ '/2026/11/24/glm54-loop-kv-decode-budget/' | relative_url }}) 的成本测量。

## 三、推理总时间几乎一样，首段开销却不同

论文用约 113M 参数的小模型做了另一组实验。以 4,096 token prefill 加 64 步单 token decode 为例，作者仓库将总时间拆成：

| 推理路径 | Prefill | Decode | 合计 |
| --- | ---: | ---: | ---: |
| OLMo3 单轮 | 18.1 ms | 982.5 ms | 1,000.6 ms |
| U-MoLT 固定两轮 | 24.5 ms | 1,443.0 ms | 1,467.5 ms |
| U-MoLT Hybrid-2 | 26.5 ms | 970.1 ms | 996.6 ms |

Hybrid-2 把重复执行移出了每一步生成。相对单轮基线，prefill 时间约高 46%，decode 时间约低 1.3%，总时间因这组测试主要花在 decode 而接近。**总时长相近不能推出首 token 延迟相近**：表中是计算阶段耗时，不含生产服务排队、动态 batching 或 P/D 之间的交接。逐 token 全串行执行 Mixture-of-Loops 而不做并行 prefill，在仓库同表的 U-MoLT 4K 测试中总耗时约 47.2 秒，说明调度路径和模型结构同样重要。

另一个质量对照用同一 checkpoint、128 token prefill 和固定续写文本比较推理调度，论文表 6 中 U-MoLT 固定两轮与 Hybrid-2 的困惑度为 26.58 和 26.56。它支持该短测范围内的预测损失相近，不替代开放式生成、长文、多并发或推理任务评估。作者仓库公开了最小 BlaGPT 实现、小规模配方和算子；不要把这些当成 64 卡 400B 训练的完整复现工件。

## 四、怎么用在自己的模型选型

如果问题是「加一轮值不值」，我会先要三张曲线：**验证损失对训练 token、FLOPs、实耗卡时**。随后用同质量检查点做推理，按输入与输出长度拆 TTFT、TPOT、有效并发、每 token KV 字节和吞吐，长 prompt / 短输出与短 prompt / 长输出都测。只有把训练和上线的成本对齐，才能区分收益来自权重复用、数据利用率，还是确实少用了机器时间。
