2026 年 11 月 22 日，OpenAI 首席科学家 Jakub Pachocki 公开了一组长期用于内部跟踪的基座模型数据：在**同一份内部代码留出快照**上，从 GPT‑3.5 的 **0.986** 到 GPT‑6.2 Astra 的 **0.761**，另有一个不具名内部模型 **0.732**。他用这条时间序列提出两个更大的问题：预训练的进步能否提前提示我们尚未在测的能力？行业能否用一组共同测量，约定何时该暂停继续推进，等监控先跟上？[原文与图表](https://openai.com/index/perplexity-and-intelligence/)

这三件事的证据强度不同。**曲线是 OpenAI 的公开测量；能力和分数的关系是作者根据历史提出的解释；0.68–0.70 和 2027 是两种外推，既不是最新实测，也不是正式安全红线。** 真正值得学的是如何把这条领先指标用进自己的研究流程，同时避免把它误当通用智力分数。

## 2. Loss 究竟在量什么：猜对只是第一步，还要看给真实答案多少概率

对固定 tokenizer、文档边界及上下文规则，将留出语料的每个真实 token 当作答案。按常见自然对数 NLL 约定：

```text
L = −(1/N) × Σᵢ ln qθ(xᵢ | 可用真实前缀)
PPL = exp(L)
exp(−L) = 真实 token 概率的几何平均
```

这是 **teacher forcing**：评分第 i 个位置时喂真实前缀，不是让模型一路自由生成。两个模型即使每步 top‑1 都猜对，一个给真实 token 0.51，另一个给 0.95，交叉熵也会明显不同。低概率真值的惩罚是对数性的；给正确结果极小概率会付出很大代价。PPL 可理解为与这份平均编码代价等效的均匀选择数，2.14 并不表示模型“每次只在两个词里猜”，其倒数也不是 token 正确率。[Hugging Face：因果语言模型 PPL 与窗口协议](https://huggingface.co/docs/transformers/en/perplexity)

按自然对数口径做三个量纲检查：

| 比较 | log-PPL 差 | 等效 PPL 变化 | 几何平均真 token 概率变化 |
| --- | ---: | ---: | ---: |
| 0.986 → 0.761，GPT‑3.5 到公开线末端 | −0.225 | −20.15% | +25.23% |
| 0.761 → 0.732，公开线末端到匿名点 | −0.029 | −2.86% | +2.94% |
| 0.732 → 0.70 / 0.68，匿名点到假设区间的两端 | −0.032 / −0.052 | −3.15% / −5.07% | +3.25% / +5.34% |

公式是 `PPL_new/PPL_old = exp(L_new − L_old)`。第一行也可写成节约约 **0.325 bit/token** 的理想模型编码代价（0.225 除以 ln 2），而不能写成能力涨了 20% 或 25%。换底时损失的数字需随底数一起换；PPL 本身可用匹配的底数恢复。**文章未披露计分的全套协议**，这些换算是帮助理解数字尺度，不是另一组实测。尤其别把 2023 年 [GPT‑4 技术报告图 1](https://arxiv.org/pdf/2303.08774) 的 **bits per word** 同 2026 年的图直接相接，两篇原文未建立相同快照、分词和归一化的合同。

### 为什么预测器也能当压缩器

如果概率模型认为某符号出现概率是 q，算术编码一类方法能使它的理想码长约为 −log₂q。编码器和解码器用**同一个模型**、同样的真实前缀，就能把模型越确信的内容写得越短。模型会后续预测变量名、括号闭合、跨文件接口约定或更长的语义依赖，可能同时提供低码长与可迁移结构。原文脚注 1 的限定很关键：**这里的“压缩器”才是那个可预测新样本的工具**，不是 gzip 打包好的训练文本。说模型学会预测留出数据，不等于证明它没记忆训练样本；若存档还要单独分发模型，也要在端到端压缩账上算模型和编码器成本。[原文脚注 1–2](https://openai.com/index/perplexity-and-intelligence/) · [DeepMind：Language Modeling Is Compression](https://deepmind.google/research/publications/39768/)

## 3. 为什么挑内部代码，而不是公开通用测试

脚注 3–4 指出，OpenAI 自 GPT‑3.5 起主要跟踪的数据来自自家代码库；这次发表的是其中的**固定留出快照**。用固定数据能减少几年之间测试题库变化，连续记下对明确分布的拟合能力；内部代码还可以包含一些不容易在公开基准上饱和的真实结构。原文并没有公开快照内容、大小、语言组成、分词方式、上下文长度/stride、跨文档处理、去重细则或误差区间。**“留出”是 OpenAI 对这套数据的说明**，外部读者无法因而独立排除样本、衍生文本或相邻历史版本的重叠，也不能复跑这些基座 checkpoint。

GPT‑2、GPT‑3 没出现在这张表里，是历史口径的一部分：作者说，按它们的训练分布，拿今天的内部代码去概括它们的通用能力不合适；若要跨这些年代比较，可以另用通用文本。GPT‑2 在旧数据集创造当时较好的困惑度、能稳定生成连贯段落；GPT‑3 展示了 few-shot in-context learning。这两段是历史背景，**没有对应本表的 loss 点**。同样，老能力榜到 GPT‑4 已有不少接近饱和、而现代题又难以公平倒测早期模型，是作者推崇长期预测指标的理由，不是放弃新任务基准的理由。[原文脚注 3–4](https://openai.com/index/perplexity-and-intelligence/) · [GPT‑2 原论文](https://cdn.openai.com/better-language-models/language-models.pdf) · [GPT‑3 原论文](https://arxiv.org/abs/2005.14165)

一个实际问题是混合权重。假设日志/模板占总 token 的 90%，其 NLL 改善 0.10；其余是稀有但重要的代码，NLL 反而变差 0.20。总 loss 仍改善 0.07。需要理解跨行、跨文件语义的那个切片，可能和总体曲线走相反方向。应该保留总体尺，也保留按语言、长度、罕见 token、上下文依赖和来源分层的尺；不能由一个总体均分倒推出困难区域。

## 4. 预训练和能力里程碑：持续改善的基底，离散变化的系统

Pachocki 把流程简化为建算力、用大规模非结构化数据预训练、再用 prompt/SFT/RL 等手段提取能力。他以前用“异质心智”比喻那个难以从设计直接推断的基底；这次也承认算法进展会模糊阶段，例如中训、持续预训和带验证奖励的训练并不是截然一道工程墙。文章用这种区分提醒：同一基座换后训练和推理配方，产品行为可以明显变化。图中几个点的含义分别是：

| 能力标签 | 原文在强调什么 | 读者不应推出什么 |
| --- | --- | --- |
| GPT‑3.5 / 0.986 | 好到能支撑早期 ChatGPT 的对话能力；助手产品还经过指令对齐和交互设计 | 把 base 直接当已经按指令稳定对话的 ChatGPT |
| GPT‑4 / 0.913 | 作者观察到显式推理能有效改善回答；后来再专门训练、激发推理 | 0.913 是所有模型获得思维链能力的数学定理；更长推理自动改动冻结基座的测试 NLL |
| GPT‑5.3-Codex / 5.4 / 0.871 | 编程从能生成片段发展为对真实工程流程有用 | 同一组代码数据既能给出工程任务成功率，也能等同后训练、工具、环境与回归测试 |
| GPT‑5.6 Sol / 0.828 | 图已经标网络安全里程碑；正文更宽泛地说进入 0.8 以下后，看到了网络安全与数学的转变 | 将背景描述当统一阈值，或将某些受控评估的能力等同任何真实环境中的表现 |
| GPT‑6.2 Astra 标签 / 0.761 | 图与正文约 0.76 的观测结合，标出开放数学任务取得突破 | 公开 API 模型单次回答解决千禧年问题，或把它绑定到 0.732 的匿名点 |

[原文与能力标注](https://openai.com/index/perplexity-and-intelligence/#base-model-log-perplexity) · [早期 ChatGPT 训练说明](https://openai.com/index/chatgpt/) · [An Alien Mind](https://openai.com/index/an-alien-mind/) · [GPT‑5.6 System Card（能力与限制）](https://deploymentsafety.openai.com/gpt-5-6)

这些是**沿历史对齐的标注，不是五个预先注册的断点实验**。平均 token loss 本来是连续量，但任务可以要求若干环节全部成功。仅作模型示意，若 30 个必要环节相互独立且每个从 0.90 改善到 0.95，整条链成功率会由 4.24% 到 21.46%；若评分只在可验收时给 1 分，台阶更显眼。另一方面，真实能力也可能因推理策略、表征或更新而出现状态变化。既不能用“连续 loss”否认能力跳变，也不能只凭一点事后贴标签断言已经找到能力相变。要验证就看同系列多个 checkpoint、统一引出配方和预算、连续子技能分数与最终 pass 指标、不同潜在阈值的误差和独立前瞻预测。[针对涌现评估的测度研究](https://papers.neurips.cc/paper_files/paper/2023/hash/adc98a266f45005c403b8311ca7e8bd7-Abstract-Conference.html)

## 5. 0.761 的数学故事：把模型、RL、推理搜索与核验分账

原文说团队用开放数学题测了超过一年，换到约 0.76 水平的模型后出现此前没有看到的结果；作者提到研究人员看见长时间关注的题在同一个讨论串里接连出现解法。这是有价值的团队观察，但没有公开统一题池上的前后通过率、分母、模型版本与推理预算对照，不能拿它估计断点、独立贡献或未来解题概率。[原文](https://openai.com/index/perplexity-and-intelligence/)

相关的 9 月 8 日 [OpenAI Navier–Stokes 技术说明](https://openai.com/index/navier-stokes-solution/) 则给了重要细节：作者说解题系统用了**比当时 GPT‑6 Astra 更强的内部模型**，在此前预训练模型上做大规模 RL，并在项目中切换到进一步训练的版本；人参与调整目标，Codex 帮助汇总此前的部分结果。成功组约 **1 万并发 agents**，距启动约 **88 小时**得到结果，另约 **17 小时**用 GPT‑6 Astra 做 Lean 形式化及验证的工作。文中单列 Navier–Stokes 约 **270 万消息、1300 亿输出 token**，多题合计约 **490 万消息、3000 亿输出 token**；不是单条轨迹，也不是包括 prefill、失败请求、工具和资源闲置在内的 FLOPs 或加速卡时。公开说明不能把构造答案、检查答案的模型和 11 月表中任一个模型点唯一对应。

数学上，OpenAI 描述的是其对 Clay 原题 **C（亦主张涵盖 D）**的有限时奇点反例，**允许光滑外力**，不是宣布证明任意无强迫流体会爆掉；公开说明中另一项无外力 Euler 结果也不能混作这一结论。Lean 检查和公开论文是证据，外界同行整理、是否满足题目原定条件、奖项程序又各自独立。Clay 9 月 11 日称结果看起来解决了问题，同时说明将按既有程序审视；OpenAI 表示不会申领奖金。由此可以理解图上的“里程碑”，但不应把企业注释改写成 Clay 已授奖或已把功劳认定给某个公开 SKU。[Clay 公告](https://www.claymath.org/news/navier-stokes-announcement/) · [奖金规则](https://www.claymath.org/millennium-problems/rules/)

性能分析上宜区分两条曲线：

1. **基座质量曲线**：同一留出快照、teacher forcing、每个 token 平均预测代价，给定权重和计分协议。
2. **任务可达曲线**：固定基座与后训练以后，随搜索预算、并发、验证器、工具权限和时间变化的正确率或首次成功代价。它适合再报每成功一题的输出 token、设备小时、验证时间和人员介入。搜索越多不保证成功越多，尤其当候选相关、验证器不可靠或容易饱和时。

理想消融应以多个相邻基座配上同规模 SFT/RL、固定 agent harness 和等额预算，分别画成功率与成本曲线，再用同基座变 RL、同 RL 变搜索。现在的公开信息支持“更强的完整系统做到了新事”，无法把突破归因到 loss 降了多少。

同一份 9 月报告还提供一组独立于千禧难题单条记录的对照：在其选取的开放数学题上，内部模型与 GPT‑6 Astra 在图中接近的相对推理算量（12.41 对 12.97）处，分别约为 **38.2% 对 14.4%**；内部模型自身随横轴 2.59 → 93.27，通过率约 26.2% → 47.4%。这说明模型差异和推理预算都能在同一次评估中看到，但横轴是归一化相对值，不是公开 FLOPs，误差条是标准误，且对照没有隔离预训练与 RL。[9 月开放数学评估图](https://openai.com/index/navier-stokes-solution/#astra-internal-model-open-math-problems)

一个更可量化的历史对照是 OpenAI 公布的 o1：AIME 2024 上单样本约 74%，64 个样本做共识约 83%，1000 个样本加学习型重排约 93%。三栏对应不同推理策略和成本，93% 不能当 pass@1，也没有任何一项更改被冻结基座的 teacher-forcing loss。这解释了作者为什么同时重视预训练指标，并主动承认它会漏掉推理阶段的变化。[OpenAI：Learning to Reason with LLMs](https://openai.com/index/learning-to-reason-with-llms/)

## 6. 曲线不是 Scaling Law：没有 FLOPs、数据和熵底，不能反推算力

这篇文章的新信息是**这组跨代公开时间序列**，并非 OpenAI 此前没有发表过内部代码损失研究。2023 年 GPT‑4 技术报告 §3 的例子恰好说明什么叫真正的 scaling 实验：作者用训练方法可对齐的小规模运行，覆盖多个已知算力级别，预测大模型终点的内部代码损失，并单独试验有限 HumanEval 子集。今天这张图的横轴是日期，不是训练 FLOPs；也没有把同一配方下的模型规模、数据量、训练复现和三个误差源一起给出。[GPT‑4 技术报告](https://arxiv.org/abs/2303.08774)

对于固定评价分布 P 和前缀规则 h，期望交叉熵可以写成：

```text
L(Q) = H_P(X | h) + E_h[ KL(P(· | h) || Q(· | h)) ]
```

第一项是可用信息条件下真分布的不确定性，第二项是概率模型还没有拟合上的部分。原文第四条限制指出，数据通常不会被完全确定地预测到，底不应简单设成 0，而且实际熵底未知。有限上下文、语料混合、分词口径不同，底也会变。**同样一个 ΔLoss，在接近非零底时可能是更大比例的可改善残差**，但不提供从残差到通用能力的通用映射。作者说越近底时小变化可能对应更大的能力跃迁，是一项经验判断，不能由分解式单独推出。

一个量纲示例：固定训练方案族，假设某一小区间的可约减 loss 符合 `L(C)=E+k·C^(−γ)`。那么从 L₁ 到 L₂ 的算量比是 `[(L₁−E)/(L₂−E)]^(1/γ)`。取 L₁=0.75、L₂=0.70、γ=0.15，若假设底 E=0.50，则约 4.4×；若假设 E=0.65，则约 102×；若 E≥0.70，前述模型下目标至多渐近可达，或不可达。全是**人为参数的敏感性例子**，不是 OpenAI 训练算量的估计；重要的是未知量会使结果相差几个数量级。[Chinchilla：含不可约项的计算最优建模](https://arxiv.org/abs/2203.15556)

同理，公开线后段降得快，可以同时来自更多算量、更好数据、架构与训练变化；某个产品点还受发布筛选。没有可比的预算和数据，既不能由 0.732 反推出 GPU 数、token 数、训练周期，也不能推导到 0.70 的年份。做集群或算法 A/B 时应分三张账：**同模型 tokens/s、MFU 与设备小时**反映系统实现，**等质量所需 token 或 FLOPs**反映样本与计算效率，**达到给定 loss 所用墙钟和加速卡时**反映整体推进速度。用快系统多跑一段和用好算法少跑一段，可以得到同一终点，但决策完全不同。

## 7. 2027 年的说法：AI 帮预训练研究加速，早于全自动递归改进

作者认为，讨论 AI 的自我改进时，常把焦点放在“人类是否退出整个研发环”。他认为那种失去人类监督的终点应避免；与此同时，**只要某个瓶颈先被解除，远不必等整个流水线自动化，进步就可能加速**。这里他点名的是预训练算法研究。类比来自开放数学：一些长期遗漏的简明想法，可能在具备能力的系统参与后集中出现。区别在于预训练依赖实验：新注意力结构、更新规则或数据方案除了想到，还要有复现实验、算量、度量和取舍。因此“早至 2027 年可能出现一波进展”是作者的情景，不是概率预测、不是 AGI 时间表，也不是拟合 0.68–0.70 得出的日期。作者还预计 AI 会帮助对齐和监控研究，但担心它们赶不上预训练的全部加速度。[原文与脚注 5](https://openai.com/index/perplexity-and-intelligence/)

对**已经发生的 2026 年**，脚注把陡降主要归给长期研究与算力投入，自动化只占较小部分，同时说最新模型已有有意义的 AI 设计贡献。被引用的 [The Jagged Frontier](https://openai.com/index/research-acceleration-jagged-frontier/#where-big-ideas-come-from) 提供的是回顾性来源调查：GPT‑6.2 Astra 有研究员报告 Codex 参与发现预训练洞见、并建议修改另一项人类提出的想法。报告还有不同的操作信号，例如人类估需 2–4 小时的研究任务，内部判定的 autonomous success 从 3 月的 23% 到 10 月的 46%；监控训练、启动训练和写推理服务代码的覆盖差异明显。它们支持“进环了，而且不均匀”，不能估出这条 loss 曲线有多少由 AI 推动。

如果真要监测这一拐点，应该追的是：agent 提案中有多少能在预注册的等预算复验转成净 loss 改善；从提出到排队、跑小规模、复现、前移到大规模的周期及耗用算量；以及扣除实验成本和监督核验后还有多少净增益。更多提交、运行次数或使用 token 是活动，不是经过检验的算法进步。

## 8. 能力变强、监控变弱，是两条要分开测的轴

Pachocki 担心，今天依赖的先读取自然语言思维链、再判断是否有风险的办法会越来越不可靠；模型也可能更能意识到自己在被训练或评估。**评估意识**指行为随“我是在测试中还是实际环境中”的推断变化；**训练意识**关乎模型是否识别当前交互及反馈会用于训练，从而在观测下改变行为。这些是需要用实验检查的风险，不是原文证实某个模型已规避任何监控。

原文链接的研究用无外显 CoT 时的任务能力、以及能否控制 CoT 可见内容等代理观察可监控性。它在其模型样本里发现，基座困惑度降低常与无外显 CoT 的能力提升相关，但任务结构、架构与后训练仍能改变结果；连续多步任务等也有例外。代理量不是线上监控漏报率，更不是按某个 PPL 点换算的失效概率。评估要把**行为是否被发现、能否及时干预、关键动作与外部证据是否留痕**与模型是否写出可读 rationale 分开。即便 CoT 仍有帮助，权限隔离、工具审计和可停止性也不能只靠自述。[CoT 生命周期研究](https://openai.com/safety-alignment/cot-monitorability-model-lifecycle/)

## 9. 共同限速提案：能力预警区间与制度阈值是两回事

原文有三层主张。第一，作者认为公布内部数值虽然给竞争对手更多信息，但共享安全依据更重要；他也链接了 Anthropic CEO Dario Amodei 关于协调节奏的文章。第二，希望开发者在前沿模型第一次使用时，就有共享评估规范、红队安全论证及透明度标准。第三，建议用 **PPL 和其他测量**设一条共同的发展上限，开发者承诺不跨，直到满足某个**具体可验证的理解或监控里程碑**，例如有一种可以接替 CoT 监控的办法；以后还可设下一条上限。[Pachocki 原文](https://openai.com/index/perplexity-and-intelligence/) · [Amodei：We Must Pace the Frontier](https://darioamodei.com/post/we-must-pace-the-frontier)

**这里没有指定第一条上限的数字。** 0.68–0.70 是作者所称可能出现未知新能力的预警窗，没给预测区间的统计置信度，也没有正式的适用模型、触发条件、审计机构、核验权限、处置程序或停训条款。它不是一个已生效的跨实验室协议、OpenAI 既有发布规则或法律。原文带来的新问题是：要在哪一阶段拿出什么证据，才能安全地继续，而不仅仅是给一个分数划线。

原文自己列的四个障碍，决定这套提案不能只用一个数：

| 障碍 | 为什么决定实务边界 |
| --- | --- |
| 跨实验室难比较 | 不同训练混合、留出集、tokenizer 与上下文。即使各公司如实报数，可能在量不同东西。 |
| 与可操作的任务脱节 | 平均代码预测好不提供罕见风险的上界。若某个占比 0.1% 的切片 NLL 恶化 2，平均只加 0.002，容易被其他域的改善覆盖。 |
| 忽略预训练以外的进步 | 同样的基座分数，RL、长推理、搜索、工具、检索和权限变化会改变能力；产品测风险要锁住这些条件，或者在合理高预算下另测。 |
| 未知熵底 | 对同一个语料也难把绝对 loss 转成剩余进步空间；更不能把一家的数值移到另一家的模型族和分布。 |

把这些障碍合起来，**更可执行的落点是用 PPL 当复评的触发信号之一，而不是安全通行证**。进入新区间，或其他能力/暴露指标显著变化，触发独立评估；不进入，不保证安全。不应把临时沙箱、扩大全时内部使用、开放 API 和开放权重合成一个“通过”。监控里程碑要预先定义风险条件、盲测漏报/误报、干预时延、日志覆盖、权限收缩、责任与停止机制；需要能检查的结果，而不是某项技术名称。OpenAI 另有其分阶段安全论证说明，可供参照，但不能当成共同标准已经落地。[Managing Frontier AI Risk](https://openai.com/index/managing-frontier-ai-risk/)

## 10. 给训练团队的可执行版本：两套 Loss 与两条验证线

- **一套固定锚点，一套滚动盲测。** 固定快照保持趋势解释，滚动盲测发现数据污染、过拟合与能力转移。按代码、自然文本、数学以及长上下文等相关域分别报数；预注册权重和 checkpoints，保留不同域及尾部，按文档或仓库做成组的 bootstrap，避免把相关 token 当独立样本导致置信区间过窄。公开哈希、评测程序和权重口径，可用第三方密封评测保护不能公开的样本。
- **同 tokenizer 报每 token 的 CE；跨 tokenizer 报可核对的每字节得分。** 以同一份可逆 UTF‑8 文本，计算指定确定分词路径上的总负对数概率，统一换成 bit 后除以原始字节数。不要混 Unicode 字符数、对数底数和 token 数。说明 BOS/EOS、context cap、窗口步长、跨文档边界、每个位置是否只计一次、分词不完全可逆时的处理。不同 tokenizer 的“同 4096 tokens”不必有同等原文上下文；每字节归一也不是把所有可能 token 切法概率求和的边际字符串似然，更不能抹平不同训练分布。可比性必须写进协议，而非只靠一个单位。[PPL 计分细节](https://huggingface.co/docs/transformers/en/perplexity) · [分词边际似然研究](https://aclanthology.org/2023.acl-short.1/)
- **能力线做受控外推，安全线做独立验收。** 训练版本、数据隔离、后训练设置和推理预算要能回溯。以多 checkpoints 的数据拟合趋势，拿测试外的一批 checkpoint 做前瞻复验。安全风险与可监控性用独立样本、实际权限和合理最坏预算测试；整条训练曲线再平滑，也不能把最后一道检查省掉。

**结论：** 这份公开数据把预训练讨论从参数规模和发布印象，推进到可复算的 14 个基座测量点；它尚未把任何新的能力换算为一条普适的 loss 阈值。最好的用法是让三张表同时存在：**留出损失衡量基座进展，预算对齐的任务评估衡量能力，独立的监控和干预验证判断能否继续推进。** 三项证据出现分歧时，分歧本身比一条漂亮的趋势线更重要。
