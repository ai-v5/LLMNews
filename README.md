# LLMNews

把公开、非敏感的每日 AI 新闻、每周 AI 专题和论文与开源项目解读，整理成可追溯的阅读体验。站点使用 GitHub Pages 和 Jekyll 构建；搜索和栏目筛选在浏览器中运行，不需要服务端或数据库。

站点：<https://ai-v5.github.io/LLMNews/>

[AI V5 项目导航](https://ai-v5.github.io/)收录本项目及其他公开项目。

编辑与公开边界见 [AGENTS.md](AGENTS.md)，可直接交给 Dot 的任务说明见 [DOT_INSTRUCTIONS.md](DOT_INSTRUCTIONS.md)。

## 添加一篇内容

1. 在 GitHub 打开 `docs/_posts/`，选择 **Add file → Create new file**。也可以在本地编辑后提交。
2. 文件名使用 `YYYY-MM-DD-英文短标题.md`，例如 `2026-11-03-open-model-update.md`。日期和文件名共同决定文章链接；发布后尽量保持不变。
3. 复制下面的模板，填写元数据和 Markdown 正文。来源使用可公开访问的原始页面；没有来源的内容不要伪装成事实报道。
4. 检查内容、链接、图片及其使用权限，确认全部适合公开，再将变更合入 `main`。GitHub Pages 会构建并发布，完成时间取决于构建队列。

```markdown
---
title: "文章标题"
date: 2026-11-03T09:00:00+08:00
summary: "一两句话说明发生了什么，以及为什么值得关注。"
section: daily
label: "AI 动态"
tags: [模型, 开源]
demo: false
sources:
  - title: "原始资料标题"
    url: "https://example.com/original-source"
---

## 发生了什么

用自己的话说明已经核实的事实，并链接公开来源。

## 我们的分析

说明推断、依据和适用边界；无法核实的信息标记为未知。
```

`section` 决定所属栏目：`daily` 为「每日AI新闻」，`weekly` 为「每周 AI 大专题」，`explainer` 为「解读专题」（如论文或开源项目解读）。每日新闻可将多条消息整理在一篇日报中；每个周专题或解读单独写成一篇文章，同一周可以发布多篇专题，数量按内容价值决定。`label` 可填写具体主题；`tags` 可按主题填写。`sources` 可以省略，填写时请使用公开的 HTTPS 链接。图片如有必要，放在 `docs/assets/` 下，使用 `![图片描述]({{ '/assets/文件名.png' | relative_url }})` 引用，以兼容项目站点的子路径；确认版权和公开范围。

日期用于展示和排序，不是定时发布开关。内容合入公开仓库后即已公开，未来日期的文章也可能在构建时直接出现在站点中；需要定时发布时，应另行设计并验证发布流程。

发布后可在仓库的 **Actions** 查看 Pages 构建状态；成功后访问文章和首页，检查链接、筛选及内容。Git 历史和公开 Pages 都是公开的，内部材料、个人敏感数据以及任何凭证都不应进入仓库。

## 托管与交互边界

GitHub Pages 提供静态文件托管：Jekyll 在发布时把 Markdown 生成 HTML，读者访问时不运行服务端代码。首页的搜索和筛选由浏览器对已发布文章执行；RSS 提供订阅。新增文章要提交并等待重新发布，不能通过网页直接写入服务器。

如果以后需要用户登录、评论、实时采集或多人在线编辑，需要另接经评估的服务，或将站点迁移至支持后端的平台；浏览器代码中不能放入私有 API 密钥。站点本身不自动抓取内容，外部任务发布的文章仍通过 Git 提交触发更新。
